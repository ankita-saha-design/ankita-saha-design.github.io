# Project Guidelines & Memory: Ankita Saha Design Portfolio

## 1. Test Footer Sandbox Workflow
* **Dedicated Preview Page:** All footer experimentation and design drafting must take place exclusively in [`preview-footer.html`](preview-footer.html).
* **Live Site Protection:** Never implement or test new footer designs directly on production files ([`index.html`](index.html), [`style.css`](style.css), or inner pages) unless the user explicitly requests to "make it live" or push changes to production.
* **Current Sandbox Features:**
  - Floating preview toolbar with instant switching between concepts.
  - **Option 7 (Live Winner):** Botanical Landscape Meadow (`#opt-7`) — Rolling green grass landscape with winding trail, featuring "Let's connect?" and social channels (Email, Instagram, LinkedIn) in signature maroon/dark brown typography.
  - **Option 6:** Cyber Matrix Platformer (`#opt-6`)
  - **Option 5:** Garden Runner (`#opt-5`)
  - **Option 4:** Botanical Tetris (`#opt-4`)
  - **Option 1:** Minimalist Editorial (`#opt-1`)
  - **Option 2:** Systems Grid (`#opt-2`)
  - **Option 3:** Warm Cream Contrast (`#opt-3`)
* **Deployment Status:** Option 7 is live across `index.html`, `play.html`, `about.html`, and all case studies in `work/`.

## 2. User & Project Context
* **User Background:** The user is a visual/creative designer, not a coder.
* **Communication Style:** Avoid unnecessary technical jargon. Provide plain-English, design-focused explanations with clear visual context.
* **Rule for Edits:** Always explain intent and strategy prior to proposing file writes or edits.
